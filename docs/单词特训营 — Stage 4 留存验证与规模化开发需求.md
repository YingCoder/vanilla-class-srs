# 单词特训营 — Stage 4 留存验证与规模化开发需求

Nov 25, 2026 · @Ellias Joseia

## 背景与目标

Stage 4 不再新增大玩法：Stage 3 的激励机制已全部开发完，但还没在真实数据库、真机和真实学生身上跑过，也没有数据回答“它到底有没有让学生多背单词”。本阶段先收口、再度量，最后补上“让学生回来”和“内容够用”两块短板。

**Stage 3 现状**：G0–F12 与 `GAME_CONFIG` 热更新均已通过三包构建、Vitest 与 Playwright 回归，学生首屏 JS 为 127.80 kB（gzip）。

**仍未验证**：

- 真实 PostgreSQL 上的 `migrate deploy`（含 `bestStage` 回填）、`seed`、并发竞态与跨日（23:59 → 00:01）测试
- iOS Safari、Android 浏览器、微信内置浏览器的真机表现（软键盘、`100dvh`、长按保存战报卡）
- 激励机制对学习行为的实际影响（目前没有任何埋点）

**Stage 4 三个目标**：

1. **收口上线**：Stage 2/3 全部待联调项在真实库和三类真机通过，并在 1 个班级灰度上线。
2. **可度量**：每个激励机制都有埋点和看板，能判断有效或无效，并能在班级间对照调参。
3. **回流与内容**：学生离开后能被温和地叫回来；邪修口诀覆盖从 136 词（19.8%）提升到至少 413 词（60%）。

**成功指标**（目标值为建议起始值，灰度满 2 周取得基线后再校准）：

| 指标 | 定义 | 建议目标 |
| --- | --- | --- |
| 周活跃天数 | 一周内至少提交 1 次评分的天数，班级均值 | ≥ 4 天 |
| 到期词完成率 | 当日已复习的到期词 ÷ 当日到期词 | ≥ 70% |
| 双环合拢率 | 当日复习环与闯关环同时合拢的学生占比 | ≥ 40% |
| 7 日留存 | 首次学习后第 7 天仍有学习记录的学生占比 | 以基线 +10 个百分点为目标 |
| 提醒召回率 | 收到提醒后 24 小时内回访的学生占比 | ≥ 25% |
| 邪修覆盖率 | 有手工口诀的词数 ÷ 688 | ≥ 60% |
| 护栏：XP 封顶触达率 | 当日达到 400 XP 上限的学生占比 | ≤ 5%（过高说明刷分或上限偏低） |
| 护栏：游戏化关闭率 | 在设置中关闭浮字、音效或榜单的学生占比 | ≤ 15%（过高说明反馈打扰） |

## 设计原则与非目标

本阶段所有需求遵守以下五条原则，延续 Stage 2/3 已确立的边界；与原则冲突的需求不进入排期。

- **激励服务记忆，不替代记忆**：奖励只挂在按时复习、答对和弱词转强上，不奖励停留时长或点击次数，延续“未到期 0 XP”和每日 400 XP 封顶。
- **服务端权威**：评分、XP、连续天数仍只由服务端计算；新增埋点通过幂等接口写入，客户端不能自行改数。
- **未成年人保护**：不展示真实姓名与全局排名；提醒不在 21:30–07:00 发送；每周提醒总数设上限；不做付费、抽奖或概率奖励。
- **教师可控**：每项新增的社交功能默认关闭，由教师按班开启，与 F9 进步榜保持一致。
- **可调可撤**：新增参数全部进入 `GAME_CONFIG` 并经服务端护栏校验，出问题可一键撤回到上一版本。

**明确不做**：抽卡或盲盒、公开全校排名、虚拟货币充值、原生 App 与 App Store 上架、家长端独立 App。

## P0 需求详述

### R1 上线收口与灰度

目标：把 Stage 2/3 文档中所有“待联调”项清零，并在 1 个班级安全灰度。

1. **真实库迁移演练**：先在含历史数据的拷贝库上执行 `20261125010000_stage3_gamification`，记录 `CardInstance.bestStage` 回填的耗时与行数，确认无误后再上生产库；之后按 `migrate deploy → build shared → seed → build server → build client` 顺序部署。
2. **集成与并发测试**：跑通 `subjectLead.integration.test.ts` 的 12 项；新增并发用例：同一 `submissionId` 并发提交只记一次 XP、同词并发评分第 3 次起 0 XP、并发下 400 XP 封顶不被突破。
3. **跨日与时区**：用可注入时钟测试上海日界，覆盖 23:59 → 00:01 的双环重置、连续天数与冻结券结算，以及 22:30 边界。
4. **真机矩阵**：iPhone Safari（含主屏幕模式与灵动岛）、华为与小米自带浏览器、微信内置浏览器；逐项检查 L5 软键盘遮挡、`100dvh`、战报卡长按保存、`speechSynthesis` 降级、返回手势、Service Worker 更新。
5. **每日账本对账**：新增定时脚本，校验学生 XP 总额等于 `GameEvent` 事件之和、不存在重复 `submissionId`、不存在负数事件；差异写入告警日志。
6. **灰度与回滚**：先开放 1 个班级（建议不超过 40 人）运行 7 天。退出条件：无 P0/P1 缺陷、对账零差异、学生端无新增 `pageerror`。回滚手段：撤回 `GAME_CONFIG`，必要时回退前端版本，预案需在灰度前演练一次。

### R2 埋点与效果看板

目标：让每个激励机制都能回答“有没有用”，并能在班级间对照调参。

1. **行为埋点与账本分离**：`GameEvent` 只记奖励，新增只增不改的 `AnalyticsEvent` 记行为。事件至少包括：应用打开、复习开始、评分提交、关卡完成、双环合拢、冻结券使用、Boss 开始与通关、徽章获得、卡牌升级、战报卡保存、热更浮条展示与点击、提醒发送与打开、游戏化设置开关。
2. **字段与隐私**：`studentId`、`classId`、事件时间（按上海日界归日）、事件类型、`props`（JSON）、客户端版本。不采集设备指纹，不接入第三方统计，原始事件建议保留 180 天后聚合归档。
3. **指标口径文档**：把“一、成功指标”中各项的 SQL 口径写成统一文档，教师端与管理端看板共用同一实现，避免口径不一致。
4. **效果看板**：在 `/teacher/game` 与 `/admin/game` 增加“效果”页，展示班级周活跃天数、到期词完成率、双环合拢率、7 日留存的 8 周趋势，以及“打开 → 开始复习 → 复习环合拢 → 闯关环合拢”漏斗，并列出徽章获得分布、Boss 参与率、周挑战参与率。
5. **班级对照**：`GAME_CONFIG` 增加发布范围 `scope`（全部班级或指定班级列表），使不同班级可在同一时期使用不同参数；服务端护栏校验保持不变。

### R3 提醒与召回

目标：学生断学后能被温和地叫回来，同时不让提醒变成打扰。

1. **站内提醒**：打开应用时若当日复习环未合拢且已过 20:00，顶部显示温和条幅，提示今日到期词数与连续天数；冻结券自动生效时说明“已用 1 张冻结券保住连续天数”。
2. **Web Push**：iOS 16.4 及以上的主屏幕网页 App 支持推送。需新增 VAPID 密钥、订阅表、`sw.js` 的 `push` 与 `notificationclick` 处理，以及“我的”页中的提醒开关。权限由学生主动开启，首次打开时不弹权限请求。
3. **降级路径**：微信内置浏览器不支持 Web Push，改用站内提醒加教师击掌（F10）；国内安卓浏览器的推送到达率未知，需在真机矩阵中实测后再决定是否承诺。
4. **频控规则**：每日最多 1 条、每周最多 4 条；仅在 07:00–21:30（上海时区）发送；学生可选提醒时间，默认 19:00；当日复习环已合拢则不发；连续 3 次未点开后自动暂停 7 天。
5. **文案约束**：不使用愧疚或威胁式措辞（如“再不学就断了”），统一正向或中性，例如“今天有 12 个词快到复习点了”。预置 6 条文案，经 `GAME_CONFIG` 可热更。
6. **教师联动**：掉队名单（连续 3 天无学习）中的学生，教师可一键发送预设击掌提醒，沿用 F10 的 6 条预设文案，不开放自由输入。

### R4 邪修内容规模化

目标：把有手工口诀的词从 136 个提升到至少 413 个（60%），并让内容生产不再只靠一两位教研老师。

1. **教师编辑工作台**：新增 `/teacher/mnemonics`，可按 Day 与“待配邪修”筛选；表单字段与现有 `MnemonicCardBlock` 一致（流派标签、一句话记忆故事、音节与字母块拆解、考场防坑提示、例句），右侧实时预览卡片。
2. **批量导入**：提供 CSV/JSON 模板下载；导入前校验必填项、长度、重复词与敏感词，导入后给出成功与失败行报告。
3. **学生共创**（默认关闭，教师按班开启）：学生对已到第 4 阶及以上的词，可提交自己的口诀。必须经教师审核才上线，审核通过后作为该词的“同学版”备选口诀展示，只显示作者昵称；作者获得“邪修创作者”徽章和固定 XP，每人每日最多 1 次创作奖励，且只在审核通过时发放。
4. **发布与撤回**：审核或导入通过的批次打包为 `MNEMONIC_PATCH`，复用现有热更新，带版本号并可撤回。
5. **覆盖率面板**：按 Day 展示已配、待配、待审核数量，作为教研进度看板。
6. **保持诚实标注**：未手工编写的词继续显示“待配邪修”，不自动生成模板套话。

## P1 需求详述

P1 在 R2 的数据证明基础机制有效后启动；若灰度数据显示双环合拢率或 7 日留存未达基线，则先调参，不上 P1。

### R5 学习搭子小队

目标：用合作而非竞争的方式增加同伴动力，避免榜单带来的压力。

1. **分组**：教师按班开启，可手动分组或让学生互选，每组 2–3 人；教师可随时调整。
2. **小队周目标**：全队每人本周至少 4 天合拢复习环即达成；达成后全员获得“小队徽章”和一次性 XP，该 XP 计入每日 400 封顶。
3. **互相击掌**：沿用 F10 的预设文案风格，学生之间只能发送预设鼓励语，每人每日最多发 3 条，不开放自由输入。
4. **隐私**：小队页只显示“本周进度条”和“已合拢人数”，不显示具体谁未学习，与 F8 班级周挑战口径一致。
5. **边界**：不做小队间排名；成员退出或转班后，其历史贡献不回收。

### R6 中考冲刺赛季

目标：临近考试时，把每日任务从“按天推进”切换为“补薄弱”。

1. **赛季配置**：教师在班级设置中填写考试日期；默认在考试前 100 天自动开启赛季，教师可提前或推迟。
2. **倒计时与目标**：学生首页显示倒计时。赛季目标为 688 词中达到第 4 阶及以上的词数，设 25%、50%、75%、100% 四个里程碑，每个里程碑发放赛季徽章和一款词卡皮肤。
3. **任务重排**：每日队列优先级为到期词、近 7 天 `重来` 的弱词、当前阶不高于第 3 阶的词；仅调整队列顺序，不改 FSRS 调度。
4. **赛季战报**：赛季结束时生成个人回顾卡，沿用 F12 的本地 `<canvas>` 生成方式，不含真名与排名。
5. **依赖**：任务重排使用 R7 的计划引擎。

### R7 智能今日计划

目标：让每天的任务量匹配学生当下的状态，既不积压也不吃不饱。

1. **投放节奏自适应**：在现有积压保护（50 词 / 回归首日 20 词）之上，当到期词积压时自动把当日新词降为 0，并把积压拆成多天的“还债计划”。
2. **加餐建议**：连续 3 天到期词完成率不低于 90% 时，提示可选的“加餐”新词；加餐不强制，其 XP 仍受每日 400 封顶。
3. **今日计划卡**：在 `/student/task` 展示“今天预计 N 分钟”，由到期词数乘以该生近 7 天平均每词用时估算；用时数据来自 R2 埋点。
4. **边界**：只决定新词投放量与队列顺序，不修改 FSRS 的下次复习时间。

### R8 教师周报与调参建议

目标：教师不用自己读看板，也能知道本周班里发生了什么、该不该调参数。

1. **自动生成**：每周一 07:00（上海时区）为每个班生成站内周报，含核心指标与上周对比、进步最大的前 3 名（沿用 F9 口径）、掉队名单（仅师长可见）。
2. **规则型建议**：按固定规则给出调参提示，例如 XP 封顶触达率高于 5% 时提示检查刷分或调高上限、到期词完成率低于 50% 时提示降低每日新词量；每条建议附对应的 `GAME_CONFIG` 参数名，仅提示，不自动修改。
3. **可留存**：周报按周存档，可在浏览器中直接打印或另存为 PDF。

## P2 储备

P2 不进入本阶段排期，只记录范围，待 P0/P1 完成且有人力时启动。

- **R9 家长周报分享卡**：在 F12 战报卡基础上生成面向家长的周报图，只含本周学习天数、掌握词数与一句鼓励，由学生本人决定是否保存分享，不含排名与真名。
- **R10 多词包支持**：把 688 词的数据结构抽象为词包，使新词表可复用卡牌、艾斯与营地地图；依赖 R4 的内容工作台。
- **R11 无障碍与低配机适配**：校验深浅两套主题的对比度，支持字号放大，尊重 `prefers-reduced-motion`（F5 已部分覆盖），并为低内存机型降级动效与卡面特效。

## 风险与待决策项

最大的风险是灰度只有一个班，样本太小，容易把正常波动当成效果；其余风险见下表，需要你拍板的 6 件事列在表后。

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 灰度仅 1 个班（≤ 40 人） | 指标波动大，难以判断机制是否有效 | 只看趋势、不下显著性结论；条件允许时灰度 2 个班作对照 |
| 寒假与春节前后活跃度下降 | P1 效果与 12 月基线不可比 | P1 灰度保留未开启的对照班 |
| 国内安卓浏览器 Web Push 到达率不确定 | R3 召回率低于预期 | 先真机实测；不达标则只承诺 iOS 与站内提醒，并评估微信渠道 |
| 学生共创出现不当内容 | 影响学生与班级氛围 | 默认关闭；教师必审；敏感词过滤；只显示昵称 |
| 奖励被刷或挤占学习动机 | XP 失去意义，学生只为奖励答题 | 沿用未到期 0 XP 与 400 XP 封顶；看护栏指标；每日对账 |
| 迁移回填出错 | 历史卡牌稀有度被错误降级或丢失 | 拷贝库演练；`bestStage` 不降级的规则加断言；保留回滚脚本 |
| 个人行为数据合规 | 学生为未成年人，埋点需要告知与同意 | 上线前向学校或监护人确认告知要求；不采集设备指纹；设保留期限 |
