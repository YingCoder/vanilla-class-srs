# 单词特训营 — Stage 3 游戏化激励开发需求

Nov 25, 2026 · @Ellias Joseia

## 一、背景、目标与成功指标

Stage 3 的唯一目标：让学生每天自愿完成「到期复习 + 当日闯关」，并把这个习惯保持到 23 天词库结束。

Stage 2 已交付完整的记忆引擎（FSRS-5 + 艾斯 8 阶段）和 688 词内容，但「明天为什么还要回来」尚未被设计。以下判断是产品假设，需在灰度中用数据验证：

- **复习靠自觉**：艾斯曲线条给出了准确信息，却没有「我完成了什么」的即时反馈。
- **闯关是单日循环**：L1–Boss 没有跨天成长线，第 3 天与第 20 天的体验几乎一样。
- **学习是孤立的**：学生之间、师生之间看不到彼此进度；教师端目前只能推送内容热更，不能做班级激励。
- **没有可积累的资产**：背过的词、攻克的弱词没有变成学生「拥有」的东西。

成功指标如下。目标数值为建议值，需用灰度首周的基线数据校准。

| 指标 | 定义 | 建议目标 |
| --- | --- | --- |
| 次日回访率 | 首次学习后第 2 天有任意学习行为的学生占比 | 较 Stage 2 基线提升 10 个百分点 |
| 到期复习完成率 | 当日已评分复习数 ÷ 当日到期数 | ≥ 70% |
| 7 日连续学习占比 | 近 7 天内学习 ≥ 5 天的学生占比 | 基线待测，灰度第 2 周定值 |
| 弱词重练参与率 | 结算页出现弱词重练按钮后的点击比例 | ≥ 40% |
| 守护：次日回忆正确率 | 第 4 阶（1 天后）复习评为「记住/秒杀」的占比 | 不低于 Stage 2 基线 |
| 守护：深夜活跃占比 | 23:00 后产生学习行为的学生占比 | 不高于 Stage 2 基线 |

## 二、设计原则与边界

游戏化只奖励真实的记忆行为，不奖励点击次数；面向初中/中职学生，宁可克制，也不制造焦虑和沉迷。

1. **奖励只来自服务端已验证的事件。** 经验值（XP）、徽章、连胜均由服务端依据 FSRS 评分与闯关结算计算，客户端只展示、不上报分数，与 Stage 2「数据权威性」一致。
2. **奖励到期回忆，不奖励刷题速度。** 同一词在到期前重复评分，XP 递减至 0；故意连点「秒杀」不会比认真复习更赚。
3. **连胜可原谅。** 断签一天不清零：提供「冻结券」自动抵一天，避免一次失误让学生放弃。
4. **竞争默认「自己比自己」和「全班共同目标」。** 班内榜只展示本周进步量而非总量，教师可一键关闭，后进生不被公开比较。
5. **每日有上限，并鼓励停下。** XP 与金币每日封顶；达成当日目标后提示「今天够了」，22:30 后不触发新的限时活动，不诱导熬夜。
6. **奖励固定可预期，不做付费与概率抽卡。** 面向未成年人，不引入任何真实货币、盲盒或随机付费机制。
7. **视觉沿用「香草单词营」糖果卡牌方向。** 日间/夜间两套主题都要适配，保持 `100dvh` 单屏约束，不新增长滚动页面。
8. **最小化个人信息展示。** 班内榜与队伍只显示昵称和头像，不显示真实姓名。

本阶段不做：实时 PvP 对战、跨班/全校排行榜、家长端、虚拟商城与任何付费入口。这些可在 Stage 3 灰度数据出来后再评估。

### G0 奖励事件账本与防刷（P0）

- 服务端新增只增不改的奖励事件账本 `GameEvent`；XP、徽章、连胜都由它派生。事件以来源记录 ID（评分日志或闯关结算 ID）为唯一键，网络重试不会重复发奖。
- 客户端不能提交 XP；界面数值一律读取服务端返回值。
- 同一词同一自然日内，评分 XP 只计前 2 次；未到期卡片的评分 XP 为 0（初记新词视为已到期）。
- 每日 XP 总封顶 400（含所有来源）。封顶后仍可继续学习，界面提示「今天够了」。
- 自然日按学校所在时区切分，默认 `Asia/Shanghai`。

### F1 经验值与营员等级（P0）

| 事件 | XP | 说明 |
| --- | --- | --- |
| 复习评分「重来」 | 1 | 诚实作答也有回报 |
| 复习评分「模糊」 | 3 |  |
| 复习评分「记住」 | 5 |  |
| 复习评分「秒杀」 | 6 | 仅比「记住」多 1，避免刷「秒杀」 |
| 闯关 L1 完成 | 10 | 每日首次 |
| 闯关 L2 / L3 / L5 过关 | 20 | 每关每日首次 |
| Boss 过关 | 50 | 每日首次 |
| 弱词重练完成一轮 | 15 | 每日最多 2 次 |
| 当日双环合拢 | 30 | 每日一次，见 F2 |

- 升级所需 XP：Lv1→Lv2 需 100，之后每级比上一级多 50（150、200……）。
- 满额打满 23 天约 9,200 XP，对应约 Lv18；多数学生达不到封顶，这是有意的留白。
- 称号每 4 级一档（建议命名）：Lv1–3 香草学徒，Lv4–7 糖霜新秀，Lv8–11 焦糖达人，Lv12–15 可可大师，Lv16 起奶昔王牌。
- 顶栏常驻一条细 XP 进度条；点开显示今日 XP、距下一级还差多少、今日封顶余量。

### 共享层

新增 `shared/gamification.ts`，与 `shared/ebbinghaus.ts` 同样是无副作用的纯函数，客户端展示和服务端结算共用同一份实现，并配单元测试：

- `xpForGrade(grade, isDue, nthToday)`：单次评分应得 XP
- `levelFromXp(totalXp)`、`titleForLevel(level)`：等级与称号
- `rarityFromStage(stage)`：艾斯阶段 → 卡牌稀有度
- `ringProgress(state, config)`：双环进度与是否合拢
- `nextStreak(prev, achieved, freezeTickets)`：连续天数与冻结券结算

### 一致性与缓存约束

- 评分写入与 `GameEvent` 写入必须在同一数据库事务内；任一失败整体回滚。
- `DailyGameState.reviewDue` 在学生当日首次请求 summary 时生成快照，避免到期数随复习进行而变化导致环忽大忽小。
- Service Worker 对 `/api/*` 仍是 Network-Only，奖励相关响应不得被缓存。
- 已有学生的 `bestStage` 用当前阶段回填；XP 与连续天数自上线日起算，不回溯历史。

## 六、教师/管理端配置与热更新

游戏化参数分两层管理：全局参数走现有热更新通道，班级参数由教师在自己班内调整。这样改 XP 表不用发版，教师也不会误改全校规则。

| 层级 | 谁能改 | 可配置内容 |
| --- | --- | --- |
| 全局（`GameConfig`） | 管理员 | XP 表、每日封顶、积压保护上限、称号区间、徽章定义 |
| 班级（`ClassGameSetting`） | 教师（仅本班） | 班内榜开关、周挑战目标、鼓励语发送 |
| 学生 | 无 | 仅可开关音效、动效 |

- **复用 Stage 2 热更新机制**：`ReleaseType` 新增 `GAME_CONFIG`，沿用 `BANNER` / `FORCE_RELOAD` / `SILENT` 三种推送模式与一键撤回（回退上一有效版本）。数值类参数建议用 `SILENT`，避免打断做题。
- **与 Stage 2 的一处差异（建议）**：Stage 2 中教师与管理员发布热更新权限对等，但 `GAME_CONFIG` 会改变全校奖励口径，建议只开放给管理员；教师只能改本班参数。此项待 PM 确认。
- **参数护栏**：服务端对每个参数设上下界（如每日封顶、单次评分 XP），超出范围的发布直接拒绝，具体范围由 PM 确认。
- **可追溯**：每条 `GameEvent` 的 `meta` 记录当时生效的 `configVersion`。参数变更只影响之后的事件，不回溯已发放的 XP。

教师/管理端接口：

| 接口 | 说明 | 权限 |
| --- | --- | --- |
| `GET /teachers/game/overview?classId=` | 看板：今日达成人数、连续天数分布、掉队名单 | 教师（仅本班） |
| `PUT /teachers/game/settings` | 榜单开关、周挑战目标 | 教师（仅本班） |
| `POST /teachers/game/cheer` | 向个人或全班发送预设鼓励 | 教师（仅本班） |
| `POST /admin/releases`（现有） | 发布 `GAME_CONFIG` 版本 | 管理员 |

学生账号访问以上接口一律返回 `403 Forbidden`，沿用 `requireTeacher` / `requireAdmin` 路由级校验。教师请求其他班级的 `classId` 同样返回 `403`。

### F2 每日双环与连续学习（P0）

- **复习环**：当日已清理的到期复习数 ÷ 当日开始时的到期数。到期数为 0 时自动满环。
- **闯关环**：当日 L1、L2、L3 全部通过；L5 与 Boss 是加分项，不计入合环。
- 两环合拢即「当日达成」：连续天数 +1，并发放 30 XP。
- **积压保护**：复习环分母最多取 50（超出的顺延到明天）。断学 ≥ 3 天后回归的首日，分母最多取 20，避免一回来就面对满屏积压。
- **冻结券**：每连续达成 7 天发 1 张，最多持有 2 张；某天未达成时自动消耗 1 张抵一天，无券则连续天数归零。界面始终显示「历史最长连续」，归零不抹掉成就。
- 入口：「特训」页顶部双环，点击展开本周 7 天的点亮状态。

### F3 23 天营地地图（P0）

地图把词库 D1–D23 变成一条跨天成长线，解决「第 3 天和第 20 天体验一样」的问题。

- 每个节点对应词库的一天（30 词，D23 为 28 词），状态为未解锁 / 进行中 / 已通关。
- 星级与真实记忆挂钩：1 星 = 当日 L1–L3 通过；2 星 = 再加 Boss 过关；3 星 = 再加该天词中 ≥ 80% 的卡牌达到艾斯第 4 阶（1 天后）及以上。3 星可在之后的复习中回头补齐。
- D7、D14、D21 为大关，D23 为终章，通关时有专属徽章与庆祝页。
- 入口：「特训」页以「本周 7 格」卡片呈现，点开可查看全图弹层；不新增长滚动页面。
- 待确认：学生的每日任务是否严格按词库 Day 推进（见第九节）。

### F4 单词卡牌收集（P0）

每个词是一张卡牌，稀有度由艾斯阶段决定，没有随机性，因此收集感直接等于记忆进度。

| 稀有度（建议命名） | 对应艾斯阶段 | 边框 |
| --- | --- | --- |
| 糖纸卡 | 初记 – 第 2 阶（30 分后） | 浅色糖纸边 |
| 银箔卡 | 第 3 阶（12 时后）– 第 5 阶（2 天后） | 银色边 |
| 金箔卡 | 第 6 阶（4 天后）– 第 7 阶（7 天后） | 金色边 |
| 闪钻卡 | 满级稳固（15 天后） | 彩虹闪边 |

- 卡牌展示「历史最高稀有度」，因一次「重来」导致阶段回落时不降级，避免挫败；当前阶段仍显示在艾斯曲线条上。
- 入口：「23天词库」页新增「词表 / 卡册」切换。卡册按 D1–D23 分 23 册，未学到的词显示为剪影，顶部显示「已收集 x/688 · 闪钻 y」。
- 点击卡牌打开现有「看邪修卡」弹窗，边框换成对应稀有度。

### F5 即时反馈与每日结算页（P0）

- 评分后 300 ms 内出现 XP 飘字与进度条增长；升级庆祝动画不超过 1.5 秒，可点击跳过。
- 全部动效遵循 `prefers-reduced-motion`；音效默认关闭，可在「我的App」开启。iOS Safari 不支持 Vibration API，触感反馈只作 Android 增强，不能成为必需交互。
- 每日结算页在现有结算页基础上增加：今日 XP、双环状态、连续天数、今日升级的卡牌、新获徽章、明日到期词数。「明日到期 N 张」是留存钩子，数据来自服务端到期队列。
- 文案不出现负面评价：全部「重来」的一轮也只提示「这些词明天会再来找你」，并保留弱词重练入口。
- 性能预算：学生首屏入口 JS 仍须低于 200 KB（gzip），Stage 2 为 117.81 kB；游戏化新增部分建议 ≤ 30 KB，动画用 CSS 实现，不引入大型动画库。

### F6 徽章与成就（P0）

首批约 18 枚，规则写成配置（`BadgeDef`），后续可经热更新增补，不用发版。

| 类别 | 数量 | 示例触发条件 |
| --- | --- | --- |
| 坚持 | 4 | 连续学习 3 / 7 / 14 / 23 天 |
| 记忆 | 4 | 累计 50 / 200 / 500 / 688 张卡达到金箔及以上（历史最高） |
| 闯关 | 6 | 首次 Boss 过关；连续 3 天 Boss 过关；D7、D14、D21 大关；D23 终章 |
| 逆袭 | 3 | 曾「重来」的词在 7 天后被评「秒杀」累计 10 个；首次弱词 Boss 获胜；单日弱词清零 |
| 结业 | 1 | 完成 D23 终章并双环合拢 |

- 徽章墙在「我的App」页；未获得的徽章显示灰色剪影与进度（如「再坚持 3 天」），让学生知道下一步目标。
- 每枚徽章只发一次，由 `GameEvent` 判定并写入学生徽章表，幂等。

### F7–F10 班级与教师驱动（P1）

P0 灰度稳定、拿到第一周基线后再开发。

- **F7 弱词 Boss**：个人弱词池 = 近 7 天评过「重来」且当前阶段 ≤ 第 2 阶的词，最多取 10 个，组成每日专属 Boss。答对扣血，答错不扣分、该词排到队尾再出现一次。击败后记入「逆袭」徽章进度。评分走现有弱词重练链路，FSRS 仍由服务端计算。
- **F8 班级周挑战**：教师每周设一个班级目标（如全班累计清理到期复习 N 张），班级 Boss 血条随全班完成量下降。目标默认值由系统按班级人数和上周实际完成量推荐，教师可改。学生只看到血条与「已参与 X/Y 人」，看不到谁没参与；名单仅教师可见。达成后全班获限定徽章与卡牌边框。
- **F9 班内进步榜**：默认关闭，由教师开启。指标是本周 XP 相对上周的增量，而非总量；展示前 10 名昵称，学生自己的名次只有自己可见。每周一 00:00 重置。
- **F10 教师激励看板与击掌**：`/teacher/game` 显示今日达成人数、连续天数分布、掉队名单（连续 ≥ 3 天未达成，仅教师可见）。教师可一键向个人或全班发送预设鼓励（6 条预设语 + 贴纸），学生下次打开时以一次性浮条展示，不打断做题，复用 `HotUpdateBanner` 的展示机制。

### F11–F13 深化与留存储备（P2）

- **F11 头像框与卡牌皮肤**：纯装饰，由等级和徽章解锁，不接任何付费。
- **F12 战报分享卡**：学生主动点击后在本地生成图片（昵称、等级、连续天数、收集数），不含班级排名与真实姓名。微信内置浏览器对系统分享支持不确定，以「长按保存图片」为主路径。
- **F13 小队连胜**：教师分 2–4 人小队，全员当日达成则小队连胜 +1，成员可互相「击掌」提醒。是否启动取决于 F8、F9 的灰度数据。
